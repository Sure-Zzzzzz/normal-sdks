# CHANGELOG - smart-kms-server-starter 2.0.1

## 版本信息

- 版本：`2.0.1`
- 基线版本：`2.0.0`
- 类型：Feature / Bug Fix，补齐本人密钥生命周期并修复管理写入边界。

## 主要变更

### 本人密钥生命周期

新增四个本人写接口，归属固定取自认证主体，只要求已有 API 权限，不要求 DATA（管理数据范围授权）：

| 方法与路径 | 能力 | API 权限 |
| --- | --- | --- |
| `PATCH /api/kms/me/keys/{keyRef}/state` | 启用或停用 | `kms.key.manage` |
| `POST /api/kms/me/keys/{keyRef}/versions` | 轮换活动版本 | `kms.key.manage` |
| `PUT /api/kms/me/keys/{keyRef}/destruction` | 按归属人政策安排销毁 | `kms.key.destroy` |
| `DELETE /api/kms/me/keys/{keyRef}/destruction` | 取消从未被后台领取过的销毁任务 | `kms.key.destroy` |

自助用户可在 `DATA=null` 时完成本人生命周期，他人密钥返回 `404`。原 `/api/kms/keys/**`
治理写接口继续校验对应 DATA，新接口不扩大跨归属人的管理范围。

### 并发、幂等与状态迁移

- 新旧接口复用归属锁、资源版本、事务和审计链，分别保存幂等作用域；历史幂等快照继续可重放。
- 管理写事务采用 `READ_COMMITTED`（读取最新已提交记录），避免获得密钥锁后仍读取竞争请求提交前的旧快照；
  不同幂等键的同资源版本竞争只允许一次成功，其余返回 `409`。
- 新旧启停命令只允许 `ACTIVE` 与 `DISABLED` 互相迁移，修复待销毁状态可绕过任务领取校验恢复或直接标为
  `DESTROYED` 的问题；取消与后台销毁的合法迁移保持原有流程。

### 请求校验与安全响应

- 本人接口严格校验 JSON 字段和类型，拒绝未知字段、重复字段、数字字符串、小数资源版本和非法状态。
- 销毁时间必须带时区，规范化为 UTC 毫秒；输入年份或换算后的 UTC 年份不在 `1–9999` 时，写入前返回
  `400`，避免将非法时间误报为持久化故障。
- 本人成功响应只包含密钥元数据，不包含归属、密钥材料或内部任务字段；取消成功为 `204`。
  JSON 编解码使用模块私有配置，合法幂等重放保留首次响应字节。

### 配套接入

更新 HTTP 契约及角色接入说明：管理员、自助用户、密码服务的默认 API 权限分别为 6、5、5 项。
自助角色增加销毁与公钥权限并保持 DATA 为空，管理员增加公钥权限并保留所需治理范围。
公钥与密码学操作仍要求同归属的精确密钥使用策略，角色授权不会自动创建策略。

可信应用注册、菜单、角色和人员准入统一维护在
[KMS Web 可信应用接入手册](https://github.com/Sure-Zzzzzz/smart-kms-admin-web/blob/main/docs/TRUSTED_APPLICATION_ONBOARDING.md)，
JSON 模板仍位于 Web 仓的 `deploy/iam/`。

## 兼容性与升级

继续使用 Core `2.0.0` 和全部既有表，无数据库迁移、新增生产依赖或历史数据重建。
IAM、AKSK 和现有 Client 不需要为本次接口增量升级。

1. 保存与 Server `2.0.0` 兼容的 Web 制品及配置。
2. 升级 Server 到 `2.0.1`，保留原数据库与治理 DATA 校验。
3. 按接入手册更新 IAM 角色规则并核验用户实际权限投影；原完整清单已声明所需权限码，标准升级无需新增码。
4. 部署 Web `1.0.0`，分别验收本人和治理操作。不能部署 `Web 1.0.0 + Server 2.0.0` 的组合。

旧治理接口的合法调用继续兼容。启停非法目标为 `400`；待销毁、已销毁密钥或不发生状态迁移的启停为 `409`。
回滚时先恢复兼容旧 Server 的 Web 制品及配置，再回退 Server。Web `1.0.0` 没有旧接口切换开关，
没有兼容旧制品时须先撤下门户入口，不能通过权限错误或接口不存在后的自动回退保持操作。

## 验证

新增 `KmsMyKeyHttpIntegrationTest`，通过真实 HTTP 和 MySQL 验证本人生命周期、跨归属拒绝、API 撤销、
旧路径 DATA 校验、幂等隔离与重放、同版本并发竞争、事务回滚、严格请求校验、时间越界、销毁窗口及历史领取后的取消拒绝。
该测试使用受控身份夹具；真实 IAM 角色投影和 Portal 接入按正式接入手册单独验收。
