# 接口契约与分页

CRM 对外 HTTP 契约的通用规矩：双模式分页、错误映射与客户端接入。完整端点清单以 [OpenAPI 契约](../../../contract/openapi/simple-crm-server.openapi.yaml) 为准，模块总览见根 [README](../../README.md)。

## 双模式分页

九个列表端点（客户/联系人/商机/目录/报价/订单/交付项/消费者/操作记录）共用两种**互斥**模式；除消费者列表外，过滤字段与 DATA 授权在两种模式下相同：

| 谁用 | 请求参数 | 响应 |
|---|---|---|
| 管理台（页码跳转/总数） | `page`（从 1 起）、`pageSize`（默认 20，1~100） | `items`+`page`+`pageSize`+`total` |
| 机器续读（增量拉取） | `cursor`（首页省略）、`limit`（默认 20） | `items`+`nextCursor`（null=末页） |

- 传 `page` 或 `pageSize` 即进入页码模式；与 `cursor/limit` 混用=400，参数出现但值为空也=400。
- `total` 是相同过滤与授权范围内的真实总数（同事务快照），不是已加载行数估算。
- 游标绑定列表族、主体、过滤条件与授权范围——条件变化后旧游标 400，须从首页重查。
- 消费者列表是页码-only（无分页参数时保留完整 `items` 兼容响应）；商机列表与客户、报价等资源一样支持两种模式，过滤条件为阶段、客户和标题/ID。
- Java 客户端（`simple-crm-client-core` 五件套）方法面为游标族 `list*`；管理台前端直接消费页码响应。

两种模式并存的原因：管理台需要跳页与总数，机器拉取需要稳定续读（keyset 在持续插入下翻页不重不漏）；license 集成端口（`pullPending(cursor, limit)`）已按游标形态对接。

## 错误映射

| HTTP | 语义 |
|---|---|
| 400 | 参数校验失败（含分页互斥/空值、body 与查询参数判别值矛盾） |
| 401/403 | 认证失败/未持所需 API 码——由身份协作底座统一给出 |
| 404 | 资源不存在或**不可见**（安全 404，不泄露存在性）；PATCH 缺判别参数同 404 |
| 409 | 聚合版本冲突 / 幂等键异参数 / 非法状态迁移 / 无可用承接方 |
| 503 | 商业能力暂不可用 |

错误响应只含安全消息、时间与关联 ID；不返回内部错误码、SQL 或领域对象未授权字段。

## 客户端接入

- **机器消费者**：引客户端五件套（javax/jakarta × RestTemplate/Feign + 共享 client-core），传输与认证由 AKSK 底座完成，方法面与游标分页语义见 `simple-crm-client-core` README。
- **管理台前端**：独立仓 `smart-crm-admin-web`（PKCE 门户接入），直接消费 HTTP 契约。
- **对账基准**：OpenAPI 文档 + 客户端契约测试逐端点钉桩（含响应字段白名单校验——服务端新增字段必须同步客户端白名单，否则真客户端拒收）。
