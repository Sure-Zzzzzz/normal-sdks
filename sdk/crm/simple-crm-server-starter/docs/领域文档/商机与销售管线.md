# 商机与销售管线

商机是客户建档后的销售跟踪聚合，记录销售机会和阶段变化；报价是冻结商业条款的独立聚合。两者有关联但不互相替代。

## 业务链路

```text
客户建档 → 商机 → 阶段推进 → 报价（可多个） → 签发 → 成交 → 订单 → 履约
```

客户必须先存在，商机创建时继承客户的 owner 与 DATA 范围。一个商机可以关联多个报价；报价也可以不关联商机，以兼容直接报价。报价是独立商业事实，允许在未确认前转移；关联商机报价转移时同步未终态商机 owner，但不改变客户 owner。商机不保存通用属性 JSON，也不引入租户字段。

## 阶段状态机

```text
NEW → QUALIFIED → PROPOSAL → NEGOTIATION → WON
                                      └────→ LOST
```

| 阶段 | 含义 | 进入方式 |
| --- | --- | --- |
| `new` | 新建机会 | 创建商机时固定进入 |
| `qualified` | 已确认机会 | 阶段 PATCH |
| `proposal` | 已进入方案或报价 | 阶段 PATCH |
| `negotiation` | 商务谈判中 | 阶段 PATCH |
| `won` | 赢单 | 关联报价确认成交事务派生，禁止人工 PATCH |
| `lost` | 输单 | 阶段 PATCH，必须携带非空 `lostReason` |

阶段只能前进不能回退（`new → qualified → proposal → negotiation` 单向推进）；`won` 和 `lost` 都是终态。终态商机不能再次推进、转移阶段或创建新的关联报价；输单保留原因用于追溯。报价确认时，报价、订单、履约项和商机 `won` 状态在同一事务中提交，任一环节失败全部回滚。

## HTTP 契约

- `POST /api/crm/opportunities`：创建商机，幂等键必填；请求至少包含 `customerId`、`title`，可选主推目录项、联系人、预计成交日期和金额。**金额与币种成对约束**：携带 `estimatedAmount` 时必须同时携带 `currency`，金额小数位不得超过该币种的默认小数位（如 `CNY` 两位）；金额以十进制字符串传递，服务端读回时按币种归一小数位，两种形态等价。
- `GET /api/crm/opportunities/{opportunityId}`：按当前主体和 DATA 范围点查；不存在或不可见统一返回安全 404。
- `GET /api/crm/opportunities`：支持 `stage`、`customerId`、`keyword` 过滤，并同时支持管理台页码和机器游标两种互斥分页。
- `PATCH /api/crm/opportunities/{opportunityId}?stage=...`：推进阶段或输单；请求体中的 `stage` 必须与查询参数一致。
- `PATCH /api/crm/opportunities/{opportunityId}?owner=...`：转移销售归属；商机以客户为归属根，转移会在同一事务内同步客户、该客户的未完结报价和其他未终态商机，目标 owner 只能来自已验证的治理授权范围。若只需交接一份报价，使用报价归属转移；关联商机报价会同步该商机，但不会改客户 owner。

阶段操作权限为 `crm.opportunity.stage`，归属转移权限为 `crm.opportunity.transfer`；创建、点查、列表分别使用 `crm.opportunity.create/read/list`。所有写操作均记录幂等事实和业务审计，重放不重复迁移、不重复审计。

## 报价关联规则

创建或编辑报价传 `opportunityId` 时，服务端校验商机与报价属于同一客户、owner 可见且商机尚未进入 `won/lost`。报价重议沿用来源报价的 `opportunityId`；不传该字段的报价保持直接报价语义。确认成交只允许已签发报价，并在同一事务内推进关联商机为 `won`。
