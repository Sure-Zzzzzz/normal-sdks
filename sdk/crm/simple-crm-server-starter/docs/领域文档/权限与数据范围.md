# 权限与数据范围

CRM 的三权模型与 PATCH 动作分派。模块总览见根 [README](../../README.md)；分页契约见 [接口契约与分页](接口契约与分页.md)。

## 三权

| 权 | 形态 | 由谁执行 |
|---|---|---|
| PAGE | `crmWeb:page` 页面准入 | IAM 门户（部署时登记，CRM 无页面） |
| API | 37 个 `crm.*` 精确码 | 控制器逐端点 `@RequireApiPermission` |
| DATA | 资源 `crm-customer` 维度 `owner` | `@CurrentDataAccessPlan` 注入，范围条件直接进 SQL |

API 判定发生在进业务代码之前，位置只看得见 URL、看不见请求体——这是 PATCH 分派设计的约束根源。

## PATCH 查询参数分派

状态变更统一 `PATCH` 资源本体，动作判别值放查询参数，Spring 按参数路由到独立方法、各挂专属权限码：

| 动作 | 判别参数 | 专属码 |
|---|---|---|
| 客户停用/复启/合并 | `?state=inactive` / `?state=active` / `?state=merged` | `crm.customer.disable/activate/merge` |
| 客户归属转移 | `?owner=目标` | `crm.customer.transfer` |
| 商机创建/点查/列表 | `POST /opportunities`、`GET /opportunities/{id}`、`GET /opportunities` | `crm.opportunity.create/read/list` |
| 商机阶段推进/输单 | `?stage=new/qualified/proposal/negotiation/lost` | `crm.opportunity.stage` |
| 商机归属转移 | `?owner=目标` | `crm.opportunity.transfer` |
| 目录上架/下架 | `?state=published` / `?state=disabled` | `crm.offering.publish/disable` |
| 报价签发/确认/撤回 | `?state=issued/confirmed/withdrawn` | `crm.quotation.issue/confirm/withdraw` |
| 报价归属转移 | `?owner=目标` | `crm.quotation.transfer` |
| 履约进度回报 | `?sequence=N` | `crm.fulfillment.report` |
| 履约人工重置 | `?state=PENDING_DISPATCH` | `crm.fulfillment.reset` |
| 重议派生 | `POST /quotations?sourceQuotationId=…` | `crm.quotation.renegotiate` |

请求体是业务载荷；携带与查询参数同名的字段时必须一致（否则 400），缺判别参数不匹配任何路由（404）。客户端由 `CrmPatchRouting`（Java）/`patchRouting`（前端）从载荷自动镜像判别参数，调用方无感。

## owner 维度与双轨

- **人员**（浏览器 PKCE 令牌）：owner=`iam:{subjectId}`，默认只见本人事实；持有 DATA 授权（如部门范围）时按授权范围扩展。owner 永远从已验证请求上下文派生，永不出现在请求体（转移的 `?owner=` 是业务目标字段，不是主体派生）。
- **机器**（AKSK 服务凭据）：owner=`aksk:{clientId}`。履约查询/回写按**派发归属**双轨（assignedConsumerId 等值），其余按 owner 等值+DATA 授权。
- **商机与报价**：商机创建时继承客户 owner，并按客户 DATA 范围治理；报价 owner 是独立商业事实，创建时要求客户/商机归属与当前主体一致，转移后按报价自身 owner 继续编辑/签发/确认/重议（客户必须仍为 active，关联商机必须未终态）。报价可选关联商机，创建时校验客户一致且商机未进入 `WON/LOST`。商机进入 `WON` 只能由关联报价确认成交派生，不另设人工越权入口。
- **报价归属转移**：未确认报价可独立转移；若报价关联未终态商机，同事务同步商机 owner，保证新 owner 可以完成确认成交。该动作不改客户 owner，也不追改已确认历史；需要移动整条客户销售管线时使用客户或商机归属转移。
- **商机转移**：商机归属以客户为根；治理转移同事务同步客户、未完结报价和同客户未终态商机，避免新的归属主体无法继续销售管线。

## 治理动作的准入

合并/转移/审计查询是跨人操作——跨人正是动作语义本身，不做 owner 等值拦截，准入完全由专属权限码（授予 supervisor/admin 类角色）控制。这就是"逐动作专属码"的意义：一个码管一个动作，角色组合即审批边界（无审批流，岗位分离走权限层）。
