# 目录与快照域

限流管理的"世界观"与"下发通道"：目录声明决定页面上能配什么，快照协议决定运行端实际执行什么。规则本体见 [精确策略域](精确策略域.md) 与 [类型化规则域](类型化规则域.md)。

## 目录（Directory SPI）

- 目录是管理端的授权数据源：服务协议模式（LEGACY_V1 / TYPED_V2）、资源与维度声明、命名空间、CUSTOM 自定义类型，以及可选的对象目录（客户、人员等稳定对象的 ID 与名称）。
- 接口为 core 契约层的 `SmartRedisLimiterDirectoryProvider`（`listServices` / `findService` / `listObjects`），宿主以部署配置或自有实现提供；管理端不做自动注册、心跳或反查。
- 引 IAM 目录适配件（`smart-redis-limiter-management-iam-directory-starter`，聚形态）时：
  - 服务清单以 IAM 可信应用注册表为权威——注册表全部启用应用均出现（显示名取注册表 `application_name`），未声明限流语义的应用资源列表为空（不可新建）；注册表停用或未登记的本地声明不出现并记录 WARN。
  - IAM 连通类故障（超时/连接拒绝/5xx）回退宿主完整声明（输出与不引适配件完全一致）；授权失败（401/403）与版本错配（404，IAM 服务端低于 1.3.7）异常原样上抛。
  - USER 维度对象检索改走 IAM 用户查询，稳定 ID 使用公开主体 `subjectId`。
  - 注册表快照内存缓存 60 秒（单飞刷新）。
- 不引适配件为散形态：纯本地声明自治（无 IAM 部署环境的合法终态）。聚散边界由依赖表达，无配置开关。

## revision 与 ETag

- `smart_redis_limiter_policy_revision` 服务级版本行：每次策略变更递增（v1/v2 同服务编码共用，一个服务只属一种协议模式）。
- 快照 ETag 由 `serviceCode + revision` 拼装（`srlm-` 前缀格式），**不依赖快照内容**——revision 不变即内容不变，这是 304 快路径正确性的基础。

## 快照协议与 304 快路径

- 运行端定时拉取 `GET /v1|/v2/policy/snapshot?serviceCode=...`，携带 `Authorization: Bearer`（人员令牌或机器凭据）+ 精确 API 码 + DATA 范围三闸；304 不绕过任何校验。
- 条件请求命中（`If-None-Match` 与当前 ETag 匹配）返回 304 空体，未命中返回 200 + 全量快照 + 新 ETag；`Cache-Control: no-cache`（可缓存但须再验证）。
- **304 查询快路径**（2.2.0 起）：先以 revision 单行拼 ETag 比对，命中直接 304，不触发全量规则查询——规则未变时（拉取的绝大多数）服务端数据库负载从"查 N 行规则+哈希"降为"查 1 行版本"。比对与全量读取之间存在 revision 变更窗口，属良性竞态：返回的 ETag 与内容仍自洽，客户端下次拉取即取到新数据。
- 协议代次（policyEpoch）与运行端 `typed.expected-policy-epoch` 不符或无快照时，运行端执行本地门禁兜底（管理端故障不导致限流失效）。

## 鉴权与授权

- API 码：`smartLimiterPolicy:read` / `smartLimiterPolicy:write`（页面与业务 API）、`smartLimiterPolicySnapshot:read`（运行端快照）；页面准入单列 `smartLimiterPolicy:page`。
- DATA 资源 `limiter-policy`：`read` / `write` 动作按 `serviceCode` 维度授权，受限范围运算 `IN`；写权限不隐含读权限，快照使用 DATA read。
- 运行端消费凭据为 AKP（服务型），最小授权不给 PAGE。
