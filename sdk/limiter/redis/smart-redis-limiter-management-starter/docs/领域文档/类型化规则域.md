# 类型化规则域（v2 多维度）

v2 策略形态：一条规则 = 七字段身份（服务/资源/计数维度/选择器/命名空间/自定义类型/对象标识）+ 一至十六个时间窗口。与精确策略域（见 [精确策略域](精确策略域.md)）并存，各走各的端点（`/v2/policy/**`），服务按目录声明的协议模式二选一。

## 表关系

```
smart_redis_limiter_typed_rule        规则主表（七字段身份唯一）
        ↓ 1:N（外键 rule_id，级联删除）
smart_redis_limiter_typed_rule_limit  窗口配置表
```

## 七字段身份

- 前两段（serviceCode/resourceCode）与 v1 同义；后五段表达"额度按每个什么发放"：
  - `dimension` 计数维度七选一：RESOURCE（资源总量）、IP（来源地址）、USER（人员）、SERVICE（调用方服务）、CREDENTIAL（凭据对）、CUSTOMER（客户合并）、CUSTOM（宿主自定义类型）。
  - `selector` 两级：DEFAULT（默认额度，每个实际对象各自一份）与 EXACT（只对 `object_id` 指定对象单独设额，其他对象不受此规则限制）。
  - `namespace` 计数空间：由宿主目录声明决定（服务端以声明对齐客户端传值，调用方感知不到纠偏）；同空间内对象互相独立计数。
  - `custom_type` 仅 CUSTOM 维度必填，且必须在目录 `custom-types` 清单内。
- 七字段组合唯一，创建后不可改：改变计数归属须新建并停用旧规则。停用 EXACT 规则后该对象回退默认额度，不影响其他门禁。

## 声明校验（目录为准）

- 资源必须声明了对应维度（`resources: {resourceCode: [维度...]}`），未声明维度创建即 400。
- 命名空间以目录 `namespaces` 声明为准，客户端传错按声明对齐（调用方无感）。
- CUSTOM 维度的类型必须命中目录 `customTypes`。
- LEGACY_V1 服务不允许出现类型化规则（协议错配 409）。

## 窗口与乐观锁

- 窗口结构、1–16 档上限、`window_seconds` 策略内唯一、整体替换语义与精确策略域一致。
- 规则行 `row_version` 乐观锁：更新/启停/删除携带 `expectedRowVersion`，不匹配 409。

## revision 与事件

- 与精确策略域共用服务级 revision 表，每次变更（创建/替换/启停/删除）递增并发布类型化管理事件（操作类型+操作人摘要）。
- 运行端通过 `GET /v2/policy/snapshot` 拉取（含 policyEpoch 策略代次），条件请求命中返回 304（快路径见 [目录与快照域](目录与快照域.md)）；代次与目录声明不符时运行端执行本地门禁兜底。
