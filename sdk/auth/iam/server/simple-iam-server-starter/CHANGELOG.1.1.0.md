# simple-iam-server-starter 1.1.0 Changelog

## 发布信息

- 版本：`1.1.0`
- 类型：Feature / 向后兼容能力扩展
- 基线版本：`1.0.0`

## 版本定位

`1.1.0` 将 Portal 侧边栏从固定扁平菜单扩展为可配置的递归菜单树，并为可信应用补齐页面权限申报、菜单可见性裁剪、页面级宿主展示模式、应用默认入口与全局无深链登录首页。已有 `menus` 调用方和已有扁平菜单数据保持可用；新接入方可逐步使用 `menuTree`、`defaultEntry` 和导航上下文获得完整路由决议信息。

## 主要变更

### 1. Portal 菜单树与兼容字段

- 新增 `GROUP` 与 `PAGE` 节点模型，支持最多四层菜单树；目录必须有子节点且不可导航，页面必须是叶子节点。
- 管理端与 Portal 返回 `menuTree`，并继续返回扁平 `menus` 兼容字段。兼容字段按树显示顺序只包含可导航 PAGE。
- 旧管理端提交与当前树等价的 `menus` 时允许原样回显；对已有层级树的改写性扁平提交返回稳定冲突错误，不会压平既有数据。
- 菜单节点支持受控图标编码；未配置图标时由 Portal 按节点类型使用稳定默认图标。
- PAGE 新增 `presentationMode`：默认 `STANDARD` 保留完整 Portal 框架；`IMMERSIVE` 仅隐藏 Portal 顶栏和侧栏，适用于报告和仪表盘等无边框展示页。模式始终由 IAM 权限裁剪后的 PAGE 读模型决定，子应用不能自行去壳；不会调用浏览器全屏，也不改变会话、路由或页面权限边界。
- 内置 IAM 仪表盘默认使用 `IMMERSIVE`：总览页无边框展示，进入用户、组织、角色、可信应用或站内信等下钻 PAGE 时恢复标准 Portal 框架；仪表盘内的会话抽屉保持在当前页。仅新安装或精确匹配 1.0 官方默认菜单的升级实例应用该默认值，已定制菜单不被覆盖。

### 2. 路由和菜单写入安全边界

- 菜单树在删除旧快照前完成整棵校验，校验失败不会留下半棵树。
- PAGE 路由限制为应用内相对路径，拒绝外部地址、协议相对地址、查询串、片段、反斜杠、字面或编码后的目录穿越，以及超过数据库列长度的输入。
- 菜单编码在同一应用树内唯一；节点名称、编码、图标、深度和页面权限引用均在服务端校验。

### 3. 默认入口与无深链登录首页

- 每个 Portal 应用可配置一个默认 PAGE 和可选静态子路径；默认入口按稳定的菜单编码保存，不依赖菜单快照重建后会变化的行 ID。
- 默认入口仅在用户访问 Portal 根路径或某个应用根路径时生效；已指定的深链、查询参数和浏览器历史不被默认入口覆盖。
- 静态子路径必须属于所选 PAGE 路由，服务端拒绝外部地址、协议相对地址、查询串、片段、反斜杠与字面或编码后的目录穿越。
- Portal 全局登录首页为单例设置，只能选择已启用且具有有效默认入口的应用；Portal 返回时已按当前用户页面权限裁剪，无法访问时自动降级到第一个可访问 PAGE。
- 菜单树、默认入口和 Portal 标量配置通过带版本号的完整快照原子更新；过期版本返回冲突，删除被选为全局首页的应用会同步清理引用。

### 4. 页面权限裁剪与清单约束

- 普通用户仅获得其应用授权行内的 PAGE；无可见子项的目录同时裁剪。
- 平台管理员以应用权限清单投影获得完整可见菜单，不需要为每个应用预置授权行。
- 平台管理员读取多个 Portal 应用时批量加载权限清单，避免逐应用查询。
- 删除仍被菜单引用的页面权限时返回稳定冲突错误，避免清单与菜单产生悬挂引用。

### 5. 内置 IAM 应用和启动引导

- 新安装默认 IAM 管理台以分组树落库，保留旧版扁平菜单配置字段作为升级兼容来源。
- 仅精确匹配 `1.0.0` 官方默认菜单的历史数据会自动升级；任何人工调整均保留。
- 启动引导在应用与权限清单准备完成后，通过与管理面相同的菜单树校验写入默认配置；非法配置使本次引导事务回滚。

### 6. Portal 管理写入审计

- 完整 Portal 配置快照提交后记录管理面 `UPDATED / APPLICATION` 事件；审计详情仅保留启用状态、配置版本、根菜单数和默认入口是否已配置。
- 设置或关闭全局无深链登录首页后记录同类管理面事件，并将当前或原引用应用作为审计目标；详情仅保留启用状态和设置版本。
- 运行日志与审计详情均不写菜单路由、应用 API 地址、OAuth 客户端密钥、会话或 Token。

### 7. 数据库与升级

- 全量 `docs/schema.sql` 包含菜单树字段、应用默认入口字段和 `iam_portal_setting` 单例表，完成标识更新为 `1.1.0`。
- 提供 `docs/migration/V1.0.0__to__V1.1.0__portal_menu_tree.sql`，用于从 `1.0.0` 原地升级；新安装执行全量 schema，已有实例按迁移说明执行一次升级脚本。

## 向后兼容性

- 既有可信应用的扁平 `menus` 数据可继续读取和使用；不要求立即迁移为 `menuTree`。
- 既有 Portal 调用方可继续消费 `menus`，升级后的调用方可消费 `menuTree` 获得完整层级信息。
- 未声明 `requiredPagePermission` 的 PAGE 继续仅要求应用准入，不改变原有应用可见性。
- 旧数据与未携带 `presentationMode` 的新请求默认 `STANDARD`，保持历史 Portal 布局；GROUP 响应固定为 `STANDARD`，请求时不得指定展示模式。
- 未配置 `defaultEntry` 时，Portal 保持按首个可访问 PAGE 进入的历史行为；升级脚本不会擅自设置应用默认入口或全局登录首页。
- 已定制的 IAM 菜单不会被启动引导覆盖；仅官方 `1.0.0` 默认扁平菜单按升级规则转换。

## 升级指南

1. 新安装执行 `docs/schema.sql`；从 `1.0.0` 升级执行 `docs/migration/V1.0.0__to__V1.1.0__portal_menu_tree.sql`，并按 `docs/migration/README.md` 完成校验。
2. 先保持既有 `menus` 接入不变；需要目录菜单时改为提交和读取 `menuTree`。
3. 为需要细粒度菜单可见性的应用申报页面权限，再在 PAGE 节点填写 `requiredPagePermission`。
4. 为无边框展示页在对应 PAGE 设置 `presentationMode=IMMERSIVE`；子应用自行提供必要的返回入口，Portal 不额外叠加悬浮控制。
5. 需要固定落点时，在管理台为应用选择默认 PAGE 和可选静态子路径；仅平台管理员可选择一个应用作为无深链登录首页。
6. 启动升级后的 IAM 服务一次，使未定制的官方 IAM 默认菜单按规则完成树形升级。
