# 权限与授权投影

IAM Server 权限域：RBAC 基础之上，应用权限清单 → 角色授权规则 → 用户授权投影的三层结构与触发语义。模块总览与端点索引见根 [README](../../README.md)。

## 统一授权投影（清单 → 规则 → 投影）

应用授权走三层结构，权限码全局命名空间（`iam:*`、`aksk:*`、`kms:*` 等，应用前缀自治）：

```
iam_application_permission_manifest   应用申报自己的码空间（事实源）
        ↓ 约束
iam_role_authorization_rule           角色 × 应用 = 权限集合（投影计算源）
        ↓ 并集聚合
iam_application_authorization         用户投影（Access Token / 验证端点的授权依据）
```

三张表的权限 JSON 落地形态（均为 JSON 字符串数组）：

**① `iam_application_permission_manifest`** — 应用权限清单（申报制，`PUT /iam/admin/trusted-applications/{id}/permission-manifest`）：

```json
{
  "rolesJson":          ["iam_admin", "iam_user"],
  "pagePermissionsJson": ["iam:user:page", "iam:role:page",
                          "iam:message:page", "iam:trusted-application:page",
                          "iam:department:page", "iam:user-group:page"],
  "apiPermissionsJson":  ["iam:user:api", "iam:role:api", "iam:permission:api",
                          "iam:message:api", "iam:trusted-application:api",
                          "iam:department:api", "iam:user-group:api",
                          "iam:dashboard:api", "iam:session:api"]
}
```

`manifestVersion` 服务端单调递增；`manifestDigest` 为各列表（角色 / 页面 / 接口 / DATA 资源）排序去重后规范化 JSON 的 SHA-256。上例即引导自动申报的 iam 应用内置清单（7 page + 9 api + 2 角色）；引导同时申报 DATA 资源 `iam:user`（动作 read / write，维度 departmentId）：

```json
"dataResourcesJson": [
  {"resource": "iam:user", "actions": ["read", "write"], "dimensions": ["departmentId"]}
]
```

**② `iam_role_authorization_rule`** — 角色应用授权规则（`(role_id, application_id)` 唯一，`GET / PUT / DELETE /iam/admin/roles/{roleId}/authorization-rules/{applicationId}`）：

```json
{
  "pagePermissionsJson": ["iam:user:page", "iam:role:page"],
  "apiPermissionsJson":  ["iam:user:api", "iam:role:api"],
  "dataGrantTemplateJson": {
    "protocol": "simple-data-permission", "version": "1.0",
    "grants": [{"resource": "iam:user", "actions": ["read"], "all": false,
                "constraints": [{"dimension": "departmentId", "operator": "IN", "values": ["1"]}]}]
  }
}
```

page / api 权限码与 DATA 模板均必须是该应用当前清单的子集：码 ⊆ 清单码表；模板每条 grant 的 resource ⊆ 清单 DATA 资源、action ⊆ 资源申报动作集、constraint.dimension ⊆ 资源申报维度集——越界即拒（`APPLICATION_AUTHORIZATION_002`）。`dataGrantTemplateJson` 为 `null` 表示该角色无数据授权。引导自动为 `iam_admin` 种入全量规则（= 清单复制 + `iam:user` all=true 模板）。

**③ `iam_application_authorization`** — 用户授权投影：

```json
{
  "rolesJson":            ["iam_admin"],
  "pagePermissionsJson":  ["iam:user:page", "iam:role:page"],
  "apiPermissionsJson":   ["iam:user:api", "iam:role:api"],
  "dataGrantDocumentJson": {
    "protocol": "simple-data-permission", "version": "1.0",
    "grants": [{"resource": "iam:user", "actions": ["read", "write"], "all": true, "constraints": []}]
  }
}
```

投影内容 = 用户当前全部角色在该应用下规则的**并集**（page / api 各自并集，无规则即空集）；DATA 同语义——投影 `dataGrantDocumentJson` = 全部角色规则模板的 grants 并集（拼接后规范化，DNF OR），无任何模板即 `null`（资源端失败关闭）。**一切权限经角色：DATA 权威通道为角色规则模板并集投影，管理面手工授权里的 DATA 编辑是重算前的临时精调，角色一变即被规则并集刷新。** `admitted` 是准入位、`status` 是授权生命周期位、`authorizationVersion` 每次重算 +1，`manifestVersion` / `manifestDigest` 记录投影所依据的清单版本。

**投影重算触发事件（五类）**：

| # | 事件 | 重算范围 |
|---|---|---|
| 1 | 准入授予 | 该用户该应用重算并置 `admitted=1`（幂等） |
| 2 | 用户角色分配 / 撤销 / 角色删除 | 已有生效投影的应用 ∪ 当前角色规则覆盖的应用；新覆盖建投影（`admitted=1`），不再覆盖的收缩为空权限集（`admitted` 不变）。角色删除级联删除其全部规则并对成员逐个触发重算 |
| 3 | 角色规则新增 / 修改 / 删除 | 持有该角色的全部用户重算该应用（无投影者新建，`admitted=1`） |
| 4 | 应用清单替换 | 规则覆盖到的用户全量重算；其余存量投影仅同步 `manifestVersion` / `manifestDigest` |
| 5 | 准入撤销 | `admitted=0` + `revokedAt`，内容保留用于追溯（幂等） |

**语义约定**：

- 例行重算（事件 2/3/4）只改权限内容与 `authorizationVersion`，不翻转既有投影的 `admitted`；准入位归准入动作（事件 1/5）管理
- 管理面手工 PUT 用户应用授权仍是直接写入口（适用无规则应用的手工授权）；其写入内容会被下一次触发事件的重算**覆盖**——配置了规则的应用以规则为准
- 清单收缩（移除码）不会自动改写存量规则，规则中越界码需管理员同步修订；重算按规则原样聚合

## 平台管理员特权（iam_admin）

内置角色 `iam_admin` 除管理台进门权（`ROLE_iam_admin`）外还携带平台管理员特权：**特权不落库、解析时合并**。授权解析（`loadActiveContext`，即 Access Token 与验证端点的投影读取）与门户可达列表发现用户有效角色（个人直挂 ∪ 部门挂载）含 `iam_admin` 时，无视该用户应用授权行的有无与状态，直接合成特权上下文：

- `admitted=true`；roles / pagePermissions / apiPermissions = 该应用**当前清单申报的全量**
- DATA：每种申报资源合成一条 `all=true` 无约束 grant（全量可见，无约束）
- 版本字段按当前清单真值（`authorizationVersion=manifestVersion`）；应用未登记清单时合成空权限集（准入但无码）
- 门户可达列表同样直通：平台管理员可见全部已启用 Portal 集成的应用

| 特性 | 语义 |
|---|---|
| 零触发器 | 应用注册不回填特权；投影重算五类事件与特权无关 |
| 即时生效 | 挂 / 摘 `iam_admin` 即时生效（解析时现查角色），无需投影重算；已签发 Access Token 的本地验签快照沿用既有 token 生命周期语义 |
| 清单跟随 | manifest 升版后特权自动按新清单全量，无存量残留 |
| 审计纯净 | `iam_application_authorization` 只存真实配置授权，特权不产生行 |
| 降权路径 | 摘除 `iam_admin` 角色（命中最后管理员保护时 409）；单应用撤销对特权不生效 |

管理面 GET 用户应用授权摘要 / 详情按用户是否平台管理员下发 `platformAdmin` 标记，管理台据此禁用撤销入口并提示降权路径。

## DATA 消费（开放 API `/iam/api/**`）

投影 `dataGrantDocument` 经 AKSK introspect 随授权快照出侧（`VerifiedResourceContext.applicationAuthorization`），由 data-permission 公共组件在开放 API 端点评估执行：

- **码 + DATA 双闸**：端点先过 `@RequireApiPermission` 精确码控（如 `iam:user:api`），再过 `@DataPermissionOperation(resource, action)` 数据范围评估——有码无 DATA 文档即 403（失败关闭）
- **读列表**：计划翻译为部门范围，与请求过滤条件**求交**（`departmentId IN 授权集`，越权数据不出库）；授权集内无可见部门时直接空页
- **读详情 / 写操作**：目标用户（或建用户的目标部门）的 `departmentId` 须完整满足至少一个 grant（同 grant 内约束 AND、grant 间 OR），越界 403
- **失败关闭**：计划不可执行（未知维度、非 `IN` 操作符、无可执行约束、值非法）一律 403，不以放宽解释执行
- 部门族（`/iam/api/departments`）第一版纯码控不挂 DATA（组织结构同步用不上部门子树递归语义）
