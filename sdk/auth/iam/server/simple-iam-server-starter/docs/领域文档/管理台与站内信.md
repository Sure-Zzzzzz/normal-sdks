# 管理台与站内信

IAM Server 管理面域：各族管理操作的统一模式、可信应用族的特殊点、SSE 站内信实时推送。模块总览与端点索引见根 [README](../../README.md)。

## 管理面操作（统一模式）

管理面各族操作走同一模式，以用户禁用为例（部门 / 协作组 / 角色 / 权限 / 可信应用 / 应用授权 / 验证客户端 / 站内信同构）：

```mermaid
sequenceDiagram
    autonumber
    participant Adm as 管理员(Vue 管理台)
    participant F as Order 4 链
    participant CS as IamAdminController
    participant US as UserService
    participant AU as 审计发布

    Adm->>F: PUT /iam/admin/users/{userId}/disable
    F->>F: hasAuthority ROLE_iam_admin
    CS->>US: disableUser
    US->>US: 最后管理员保护（最后一个可用管理员 → 409 Conflict）
    US->>US: 置 INACTIVE + revokeAllByUserId 全端吊销
    US->>AU: publishAdminAction(DISABLED, USER, …)
    AU-->>AU: AFTER_COMMIT 投递审计
    CS-->>Adm: 200
```

可信应用族的特殊点：创建应用必须带初始客户端，CONFIDENTIAL 初始客户端密钥留空时由服务端生成，创建响应（`initialClientSecret`）与应用下新增客户端响应均仅返回一次明文，后续查询仅 `secretPresent`；级联删除顺序为菜单 → Portal → 权限清单 → 授权规则 → 应用授权投影 → Consent 投影 → 客户端 → 应用。

## SSE 站内信实时推送

```mermaid
sequenceDiagram
    autonumber
    participant Adm as 管理端
    participant MS as MessageService
    participant Pub as Redis Pub/Sub
    participant SA as MessageSseService(实例A)
    participant SB as MessageSseService(实例B)
    participant B as 浏览器(多端)

    B->>SA: GET /iam/web/messages/events（每端一条长连接）
    loop 每 30s
        SA-->>B: 心跳注释帧
    end
    Adm->>MS: POST /iam/admin/messages
    MS->>Pub: 广播 UNREAD_COUNT(userId)
    Pub-->>SA: 实例A收到
    Pub-->>SB: 实例B收到
    SA->>SA: 推送前懒校验（只读校验用户/会话状态，不续期）
    SA-->>B: 未读数事件（best-effort，推送失败不阻塞主流程）
    Note over SA,B: 三道防线：30s 心跳保活 / 推送前懒校验防向已吊销会话推送 / 30min 连接超时兜底
```

跨实例：用户连接在实例 A、站内信从实例 B 进来，靠 Pub/Sub 广播三类消息（`UNREAD_COUNT` / `EVICT` / `EVICT_HASH`）保证两端都推到。
