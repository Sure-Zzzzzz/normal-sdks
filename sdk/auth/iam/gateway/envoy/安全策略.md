# Gateway 安全策略

## 控制面

xDS（Envoy 动态配置协议）gRPC 端口只允许 Envoy 访问，并由网关控制面区和网络 ACL 限制；入口后链路不启用 TLS/mTLS，不能暴露到统一入口层之外。Envoy admin 端口只绑定 loopback 或管理网，禁止入口侧访问配置导出、集群和运行时修改接口。

部署边界必须按职责分为统一入口区、网关数据面区、网关控制面区和业务应用接入区。IAM Nginx
只能访问统一入口区及其允许的网关数据面连接，业务 Nginx 只能接受来自网关数据面区的连接，
Envoy 才同时连接统一入口区和业务应用接入区；adaptor 到 Envoy 的 xDS 连接单独受网关控制面区的
ACL 保护。任何业务 Server 的宿主端口、adaptor
readiness 端口或 Envoy data plane 宿主映射都不能成为统一入口的替代路径；本机诊断映射
必须绑定 loopback，并在验收中证明它不能绕过 IAM Nginx 和 Envoy 的认证边界。

## 平台保留路由

IAM Nginx 是外部统一入口，先处理 `/`、Portal 壳、`/app/iam/**`、`/app/aksk/**`、`/iam/**`、`/oauth2/**`，以及 AKSK 固定 API `/api/client/**`、`/api/me/aksk-clients/**`、`/api/token/**`、`/api/application-authorization/**`。这些平台保留路径不进入 adaptor 快照或 Envoy xDS；IAM 与 AKSK 即使作为可信应用记录出现在目录中，其平台 Web 仍由 Nginx 自闭环。业务可信应用只能使用不覆盖保留路径的 `routePrefix`，由 Envoy 按投影转发。

## 目标地址

可信应用目标地址只来自 IAM Portal 机器投影。Adaptor 在发布前执行：

- scheme 只能是 HTTP；HTTPS upstream 会被 adaptor 拒绝。拒绝 userinfo、空 host、控制字符、非法百分号编码、Unicode 混淆主机和 IPv6 zone id；
- host、port 必须符合部署运行目录的 allowlist，默认拒绝回环、云元数据、未授权私网和不允许端口；
- DNS 解析后的每个 IPv4/IPv6 地址再次执行同一网段策略；通过校验的地址以 EDS 固定下发，Envoy 禁用 `STRICT_DNS`；
- xDS 仅发布 HTTP upstream，不生成 TLS transport socket、不配置 SNI、证书或 CA；
- Gateway 不跟随上游 3xx 重定向；响应由上游返回给调用方。入口与目标检查不扩展到重定向目标。

IAM 当前登记逻辑要求动态应用的 `entry`、`apiBase` 和 `targetOrigin` 完整；fragment、query、路径编码和 SSRF 边界由 adaptor 在快照阶段拒绝，不把不安全值静默修正或发布。`targetOrigin` 是唯一机器目标，页面/API 公共字段不得混入业务连接 origin。

## 请求和响应边界

- 入口先清除客户端提供的 `X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host` 和 `X-Request-ID`，再由受控入口生成；Envoy 只信任明确配置的入口跳数，并向上游发送规范化值。除明确允许的转发头外，客户端自带的内部 `X-*` 头全部删除，不能把任意自定义头当作 IAM 事实。
- Envoy 使用登记目标主机生成 HTTP Host/`:authority`；原始入口主机名只作为受控 `X-Forwarded-Host`。
- IAM 1.3.8 Portal 路由投影固定返回 `forwardAuthorization=REQUEST`，adaptor 原样转发浏览器入站 Authorization，使业务 Nginx/API 验证其自身 Bearer 凭据；IAM、adaptor 和 Envoy 均不生成、验证、解析或记录该凭据值。通用路由策略 `NONE` 会移除 Authorization。Cookie 始终移除，非空 Cookie 白名单会拒绝发布快照，避免整段 Cookie 泄露。IAM 会话 Cookie、内部管理头和 Gateway 自己的凭据永不转发。
- Gateway 不生成、解析、持久化或记录凭据；Resource/业务应用自行验证转发的凭据并执行 PAGE/API/DATA 授权。
- Gateway 当前未提供请求体大小、连接数、并发、上传/下载时限或流式协议的专用策略配置；这些限制须由入口代理和可信应用各自的部署策略承担，不应将其视为 Gateway 已实现的保护。
- Gateway 不校验或改写 `Set-Cookie`、`Location` 等上游响应头，也不改写 HTML/JavaScript。可信应用必须自行返回适用于其 `routePrefix` 的资源和响应头。
- 未命中返回统一 404；无快照、xDS 未就绪或上游不可达返回统一 503，不泄露上游地址和内部异常。健康端点只证明对应进程或控制面状态，不能证明统一入口、业务认证、授权投影或业务 API 已通过。

## 入口侧 TLS

如入口侧使用 HTTPS，只在外层防火墙、硬负载或 IAM Nginx 终止 TLS。IAM Nginx 到 IAM 服务、Envoy 和业务可信应用均使用 HTTP；Gateway 和部署运行目录不管理入口私钥，不挂载上游 CA 或应用证书，也不配置 SDS（Secret Discovery Service，动态证书下发）。这不允许业务 Server 直出宿主端口，也不允许把 HTTPS upstream 混入本链路。

## 观测与事件

日志只记录 applicationCode、route/snapshot 版本、受控目标摘要、HTTP 状态、耗时和受控 `X-Request-ID`；同步事件另用 `correlationId`。当前静态 adaptor 摘要为 SHA-256，部署运行目录可在不改变事件字段的前提下替换为 HMAC-SHA-256。禁止记录 Authorization、Cookie、Token、密码、私钥、完整 URL Query、完整 Header、请求 Body 或响应 Body。
