功能说明

用户级 AKSK 支持在换取 Token 时传递自定义业务上下文（security_context），该上下文会被编码到 JWT Token 中。

它由 Client 自行提交，仅用于业务上下文传递，不是可信的 API permission 或 DATA 授权来源。

仅用于本地演示：不要粘贴生产环境的敏感业务数据。

步骤1: 携带Security Context换取Token
只有用户级AKSK支持security_context
可以是任意JSON格式的数据,建议使用对象格式便于解析
步骤2: 服务端验证结果
Token 不会回显或交给浏览器解析。页面仅通过带认证 Introspect 展示服务端验证状态和 security_context。

使用说明

            

            

                
1. 创建用户级AKSK

                
在 创建用户级AKSK 页面创建一个用户级的Access Key和Secret Key。


                
2. 携带 Security Context 换取 Token

                
在 OAuth2 Token 请求中添加 security_context 参数。实际凭据和 Token 仅在受保护的请求中传输，不在页面结果区回显。
                


                
3. 服务端验证 Security Context

                
页面通过带认证 Introspect 请求，由服务端验证 Token 后仅展示 security_context 业务上下文；不会在浏览器端解密或解析
                    Token。


                
4. 后端验证Security Context

                
在 API 端点中，可以从 JWT 中提取 security_context 作为业务上下文；API permission 和 DATA 授权必须使用
                    aksk_authorization 快照完成校验：

                
// Spring Security获取JWT claims
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
Jwt jwt = (Jwt) auth.getPrincipal();
Map<String, Object> securityContext = jwt.getClaim("security_context");

String tenantId = (String) securityContext.get("tenantId");
